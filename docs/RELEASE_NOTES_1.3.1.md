# 选文送 AI v1.3.1 · 框选启动与任务卡住修正

浏览器扩展 **1.3.1**；Harness 接收插件继续使用 **1.2.1**，明确适配 dsh rc.2 / rc.5。

## 修正

- 开始框选时允许插件弹出面板持有焦点；截图和自动交付时仍要求原网页处于前台。
- 不再把页面加载资源的 `loading` 状态直接当作刷新。实际跳转、标签页切换、文档变化与截图前后的位置变化仍会中止任务。
- 修正识字文档对后台消息 `sender.url` 的过严要求，兼容本扩展无 tab 且 URL 缺省的 service worker 消息；其他扩展、网页内容脚本和不符合来源检查的消息仍被拒绝。
- 识字组件必须返回带当前任务 ID 的启动确认；缺失确认、错误 ID 或超时会报错并释放任务，避免静默卡住。
- Chromium 116–149 使用 `runtime.getContexts` 检查识字文档，不依赖 Chromium 150 才加入的 `offscreen.hasDocument`。
- 面板新增就近显示的 OCR 进度与“取消识字任务”按钮；更新 / 重新加载扩展时取消旧识字任务。网页输入框自身的失焦不再被当作浏览器窗口失焦。

## 验证范围

**76 项自动化检查通过。** 在真实浏览器 Worker 中运行实际 OCR 控制器、识字模块和本地引擎，7 项联调检查通过：无回执恢复、取消卡住任务、四种语言的双行文字预览，以及一次真实本地 HTTP POST。

联调中的浏览器 API / 扩展消息传递身份为模拟适配层，OCR 与 HTTP 为真实执行。这不代替在已安装 Edge / Chrome 扩展中测试原生截图、权限及最终 Harness 草稿写入。独立原生扩展自动化仍受环境进程权限限制；新版尚未上传 GitHub 或执行远程 CI。

## 更新后复测

1. 用新版扩展文件更新当前加载的扩展目录，并在扩展管理页点击重新加载；确认版本为 **1.3.1**。
2. 关闭旧插件面板 / 设置页，并刷新需要识别的网页，清除旧框选脚本。
3. 打开插件，若仍提示旧任务，点击 **取消识字任务**。
4. 首次关闭自动交付，框选一小段清晰文字；应看到网页处理中提示与面板进度，完成后结果在“手动输入 / 重新发送”文本框中。
5. 确认识别文字后，再开启自动交付，测试 dsh 草稿写入。现有接收插件 1.2.1 和配对设置不需要重装。
