# dsh 升级到 rc.5 后重新连接

## 为什么显示异常

接收插件 **1.2.0** 声明仅支持 `dsh 0.2.1-rc.2`。dsh 升级为 `0.2.1-rc.5` 后，运行时会阻止这个旧包加载，所以没有接收组件运行。无需填写模型 API Key，也不应强制跳过兼容检查。

新版接收插件 **1.2.1** 明确支持 `0.2.1-rc.2 || 0.2.1-rc.5`，不包括尚未验证的 rc.3、rc.4 或其他版本。浏览器扩展 1.3.0 可继续使用。

## 安装适配包

1. 在 dsh 插件页面停用旧的 `@local/harness-webclip`。
2. 通过 **插件 → 添加插件 / 安装第三方插件**，选择 `harness-webclip-1.2.1.tgz`，然后启用。若界面不能直接更新同名包，先卸载旧接收插件，再安装新版；保留本机 `webclip-to-ai/connection.json`。
3. 确认插件版本为 **1.2.1**，显示 **运行中**。
4. 打开浏览器扩展的接口设置，重新选择现有 `connection.json`，点击 **保存 Harness 本地连接**并授权本机地址。通常位于 `~/.dsh/webclip-to-ai/connection.json`，设置过 `DSH_HOME` 时以该目录为准。
5. 在 Harness 打开普通聊天并保持草稿可编辑，点击扩展设置中的 **发送测试文本**。出现草稿文字后再试网页选文或框选识字；消息仍由你手动发送。

不要把配对文件作为插件包安装，也不要将它上传到 GitHub。
