# 框选图片文字：v1.3.1 本地候选版

## 升级与使用

1. 保留本机配对设置。若 dsh 已升级到 rc.5，请先将 Harness 接收插件更新到 1.2.1；[连接说明](DSH_RC5.zh-CN.md)。rc.2 用户可继续使用已有兼容接收包。
2. 解压 `webclip-to-ai-extension-v1.3.1.zip`。在 Edge / Chrome 扩展管理页，将现有扩展更新为这份文件夹内容后点击重新加载；继续使用同一个扩展目录可以保留原配置。如果新加载成另一份扩展，需要在新扩展中重新导入本机配对文件。
3. 确认浏览器扩展版本为 **1.3.1**，浏览器内核版本至少为 116。
4. 在插件面板选择识别语言：简体中文、繁体中文、日文或英文。中日文模式同时识别英文。
5. 在 Harness 打开想要接收文字的会话，保持草稿可编辑。
6. 回到网页，按 **Alt + Shift + O**，拖动框选图片中的文字区域，松开鼠标后识别并交付到当前配置的智能体。
7. 切回 Harness 检查识别文字，再手动点击发送。OCR 可能误识，尤其是小字、模糊图、竖排和复杂背景。

也可以点插件面板中的 **框选识字**，或在网页 / 图片上右键选择 **框选图片文字并交给 AI**；右键入口仍需要框选，不会自动识别整张图片。

## 首次试用

建议先取消勾选 **识别后自动交给已连接的智能体**。框选后打开面板，在“手动输入 / 重新发送”中检查和修改结果，再点击交付按钮。确认效果后可以重新开启自动交付，后续只需快捷键和框选。

快捷键冲突时，在 `edge://extensions/shortcuts` 或 `chrome://extensions/shortcuts` 中给“框选图片文字并交给 AI”重新分配组合键，或使用面板按钮。

## 取消与失败恢复

- 框选时按 Esc 取消；窗口缩放、滚动或失去焦点也会取消框选。不要在框选过程中移动页面。
- 只支持当前网页可见区域；先滚动到目标图片，再启动框选。
- 图片本身可以来自其他域名，因为识别使用当前标签页的截图；浏览器保护页面、扩展商店、受保护的视频画面等仍可能无法截图。
- 识别期间切换网页、刷新页面或更改智能体连接设置，将停止自动交付；已识别出的文字保留在插件面板中供手动恢复。
- 识别大约两分钟仍未完成会中止。无结果时确认识别语言、放大原图或缩小框选范围再试。
- 每次只处理一个识字任务，不会因为同一完成回调重复交付。网络超时后请先查看 Harness 草稿，再决定是否重发。
- 自动交付使用识别完成时 Harness 当前可接收的会话；在识别和交付期间保持目标会话不变。接收插件本身继续检查交付期间的草稿和会话变化。

## 图片与数据

截图和裁剪仅在本机内存中处理，不上传识图服务，也不写入会话存储。只把识别出的文字和配置模板指定的来源字段交给你已配置的接收接口。识别语言与自动交付开关保存在本机，最近结果在浏览器会话中暂存。

OCR 引擎、WebAssembly 与四种语言模型包含在安装包内，识别时不下载脚本或字库。接收端交付依然需要相应连接。构建者首次准备资源需要联网，见 [第三方许可](../THIRD_PARTY_NOTICES.md)。

## 已验证与待验收

- 旧版 38 项检查继续通过，新增 OCR 流程 18 项检查通过，真实打包 WASM 的四种语言双行清晰文字样例通过，v1.3.0 当时共 **60 项自动化检查**。
- 在应用内浏览器运行实际 `ocr-offscreen.js`、浏览器 Worker、本地模型和受限 CSP，四种语言的双行样例通过。测试用的消息路由为模拟接口，不代表实际安装的 Chrome / Edge 扩展已经通过端到端验收。
- 本机独立测试浏览器因进程权限被拒绝启动，`npm run test:browser` 尚未执行成功。没有通过降低浏览器安全设置来绕过该限制。
- **仍待用户协助验收**：实际 Edge / Chrome 快捷键是否分配、原生 activeTab 授权、`captureVisibleTab` 与正式 offscreen 文档消息路由、真实网页框选以及最终 Harness 草稿插入。未将旧版本的原生选文验收视为新版 OCR 的原生验收。
- 没有覆盖任意图片、手写体、竖排日文、表格结构还原、扫描 PDF 整本解析；不承诺识别完全准确。
- v1.3.1 尚未上传 GitHub 或执行远程 CI；已发布 v1.2.1 的 CI 成功不代表这一候选版 CI 已通过。
