# 常见问题

## 两行选文被合并成一行

旧浏览器扩展直接使用右键事件的 `selectionText`，部分 Chromium 页面会在该字段里折叠换行。请将**浏览器扩展**重新加载至 1.2.1，Harness 接收插件保持 1.2.0 即可。

新版本在用户点击右键交付时按需读取原始选区，并与原生事件的文字核对，只恢复相同选文的空白格式。不增加全站常驻脚本或额外权限。浏览器禁止读取选区的受保护页面仍回退到原生选文，该路径的换行可能受浏览器影响。

## 没有 DeepSeek Harness 桌面版区块

通常是旧设置页或旧目录。关闭设置页，到浏览器扩展管理页查看「选文送 AI」版本，确认是 **1.2.1**，重新加载后再打开设置。新版区块在页面顶部，并带有配对文件导入入口。

## 点击右键菜单后没反应

在普通网页上，应看到页面内提示。浏览器受保护页面可能无法注入提示，此时点扩展图标查看最近状态。如果面板也打不开，到扩展管理页查看是否有 **错误**，报告第一条错误内容并隐藏凭据。

还没设置接收地址时，插件会保存选文并打开设置页。示例地址只是输入提示，不能接收文字。

## 找不到 connection.json

请先确认 Harness 接收包已安装并 **立即启用**，且没有运行时不兼容或端口冲突错误。默认路径为 `~/.dsh/webclip-to-ai/connection.json`；Windows 是 `%USERPROFILE%\.dsh\webclip-to-ai\connection.json`。自定义 `DSH_HOME` 时请在该目录查找。

文件由接收插件启动时生成，不是 Release 附件。它不应该出现在 GitHub 源码里。

## HTTP 401 / 配对码不匹配

重新导入当前 Harness 生成的配对文件并保存。升级公开版时不要继续使用旧测试包中的固定配对码。通用接口的 HTTP 401 则需要检查你自己的接口认证配置。

## 无法连接 Harness 接收插件

保持 Harness 运行；确认接收包启用并成功绑定端口。默认地址为 `http://127.0.0.1:18766/receive`，不是 Harness 主服务的随机端口。不要同时启用两个接收包。

真实运行时验收中曾遇到已有接收器占用默认端口的情况。仅看到配对文件或端口有响应，不代表当前实例已成功启动。请查看当前接收包是否报 `EADDRINUSE`；新旧接收包并行时，先停用旧接收包，再重启当前接收包并导入其配对文件。

## 提示先打开普通会话

在 Harness 桌面版打开目标普通会话，使其输入框可编辑，等待约一秒，再交付。当前版本不写入 Harness Web 页面、空白欢迎页或不可编辑的命令输入状态。

## 草稿编辑或切换会话后交付失败

插件会拒绝过期的草稿修订或会话。回到正确会话，确认草稿内容后再次交付。文字不会被自动改投到另一个会话。

## 超时后要不要重试

先检查 Harness 输入框或自建接收端。超时意味着没及时收到确认，文字可能已经写入；不要把超时当作“肯定没收到”。插件不会自动重新发送。

## 想使用 Kimi / Gemini

在 Harness 里配置并选择相应模型。选文插件只交付草稿，不管理模型账户。直接填入 Kimi / Gemini 的聊天网页属于另外的网页适配，目前尚未实现。

## 需要提交什么信息

提供扩展版本、浏览器名称和版本、操作系统、Harness dsh 运行时版本、复现步骤、实际提示。不要上传配对文件、API Key 或真实敏感选文。[验收范围](TESTING.md)说明了目前已验证与待验证的部分。
