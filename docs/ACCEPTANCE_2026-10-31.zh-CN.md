### 11 项真实运行时接入检查

1. 内部 poll 路由拒绝未认证请求，返回 HTTP 401。
2. 已认证 poll / ack 路由正常注册并响应。
3. 本地接收请求经过真实 Host、实际 Client 代码和模拟编辑器，再通过真实认证路由回传写入确认。
4. 已有草稿和被选中的草稿文字保留。
5. 交付期间修改草稿修订，拒绝过期写入。
6. 交付期间切换当前会话，拒绝投递到错误会话。
7. 模拟确认丢失后，下一次真实路由轮询不会重复插入。
8. 通过实际 Cordis HMR 停用 bundle，待处理请求返回 HTTP 503 并取消。
9. 停用后，本机接收端口释放。
10. 通过实际 HMR 重新启用后，端口和内部路由恢复。
11. 重新加载后，本机配对令牌保持不变。

### 运行时版本拒绝

## 发现的环境问题

### 默认端口已有接收器

独立实例首次使用默认接收端口时，目标端口上的接收器不接受新配对文件的凭据，且新实例未注册内部路由。测试改用独立端口后，安装、启动与路由检查通过。没有为了验收关闭日常使用的接收器。

因此，新旧接收包并行运行时，需要检查端口冲突。端口响应或配对文件存在，都不能单独作为“当前实例已正常加载”的证据，应同时验证对应实例的认证 health 与内部路由。

### 桌面与浏览器控制受阻

- Harness 的无障碍界面文字可读取，但画面捕获连续返回 `window capture timed out` / `FrameArrived timed out`。元素点击也曾返回 `coordinate input geometry is unavailable`。
- 本次会话尝试创建独立 Edge 和 Chrome 验收浏览器，分别返回 `Browser is not available: edge` 和 `Browser is not available: chrome`。
- 插件目录搜索没有找到可以直接补足本机 Chrome / Edge 控制的连接，未推荐无法访问本机实例的云浏览器来替代原生扩展验收。
